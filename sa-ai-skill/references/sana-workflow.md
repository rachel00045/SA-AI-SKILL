# Sana 需求分析與 UC 流程

本流程整理自 Sana 的需求分析、決策記錄、UC 與測試追溯做法。在同一個專案內依下列順序執行。

1. **盤點來源。** 確認專案、角色、功能邊界、成功條件和交付物。列出需求、會議記錄、舊 UC、畫面與相關工項，記錄版本、日期及出處。把已確認需求、建議、推論和待確認分開。程式與畫面是現況證據，業務規則以已核准的來源為準。
2. **逐題釐清。** 按依賴順序處理角色、權限、流程、狀態、欄位和驗收條件。遇到會改變規格的缺口，先查來源，再問一個具體問題。記下決策編號、問題、答案、狀態、來源、確認人、日期、受影響的 UC 及影響。獨立部分照常處理。
3. **撰寫 UC。** 依專案既有格式記錄 UC 編號、版本、來源、角色、前置與後置條件、基本流程、替代及例外流程、規則、欄位與權限、版本紀錄。讓規則和流程步驟可被引用。未確認內容保留待確認。有專案 Word 範本時，從副本開始並保留原有格式與版本歷史，完成後檢查變更頁面及相鄰分頁。缺少正式範本時可先交付 Markdown 草稿。以實際檢查結果說明 Word 的版面驗證狀態。
4. **建立測試追溯。** 依基本、替代和例外流程，以及必填、格式、邊界、狀態和權限規則抽出案例。記錄對應的 UC 版本／步驟、角色、前置條件、資料、操作及預期結果。執行後再補實際結果、狀態與佐證，使用 `pass`、`fail`、`blocked` 或 `not-executed`。
5. **交接與檢核。** 核對來源、決策、UC、測試、變更是否對得起來。若要整理 TFS 議題，依本 Skill 的開立流程將可獨立驗收的工作寫成草稿，連到 UC 與佐證。保留影響正式規格的待確認項目，並說明下一步需要的決定。
